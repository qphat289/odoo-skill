# Odoo Presales

Use this skill when the task happens before coding starts, or when project delivery needs cleaner business-to-implementation handoff.

## Quick reference

| Topic | File | When to use |
|---|---|---|
| Discovery workshops | `references/discovery-questionnaire.md` | Collect requirements and business context |
| Fit-gap classification | `references/fit-gap-analysis-guide.md` | Map requirements to fit, config, custom, integration |
| Rough estimation | `references/effort-estimation-guide.md` | Size work before planning or proposal |
| Proposal and SOW structure | `references/proposal-sow-templates.md` | Build commercial and scope documents |
| Handoff to implementation | `references/implementation-handoff-guide.md` | Convert signed scope into `01-business-to-implementation-spec.md` |
| Scope artifact template | `references/business-to-implementation-spec-template.md` | Write the final business-to-build scope document |

## Rules

1. Use this skill before `odoo-planner` when the scope is still business-facing or ambiguous.
2. Keep business requirements traceable from discovery to fit-gap to `01-business-to-implementation-spec.md`.
3. Do not mix signed scope, exploratory ideas, and phase-2 backlog in one table.
4. When a requirement is not confirmed, label it as an open question instead of turning it into implementation detail.
